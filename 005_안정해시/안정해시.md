# 안정 해시 & 가상 노드 정리

> 💡 **수평적 규모 확장성** 달성 = 요청 또는 데이터를 서버에 균등하게 나누는 것

---

## 안정 해시란?

- 해시 테이블 크기가 변경될 때
- 오직 **`k`(키의 개수) / `n`(슬롯의 개수)** 의 키만 재배치하는 해시 기술

### 기본 절차

1. 서버와 키를 균등 분포 해시 함수를 사용해 **해시 링**에 배치한다.
2. 키의 위치에서 링을 **시계 방향**으로 탐색하다 만나는 최초의 서버가 키가 저장될 서버다.

### 이랬을 때의 문제점

- 파티션의 크기를 균등하게 유지하는 게 불가능하다.
- 키의 균등 분포를 달성하기가 어렵다.

### 해결 방법 — 가상 노드(virtual node) / 복제(replica)

- 키의 위치로부터 시계방향으로 링을 탐색하다 만나는 **최초의 가상 노드**가 해당 키가 저장될 서버.
- 가상 노드의 개수 증가 → 키의 분포가 점점 더 균등.
- 그러나 가상 노드 데이터를 저장할 공간이 더 필요 → **tradeoff (타협이 필요)**

---

## 안정 해시의 이점

- 서버 추가/삭제 시 재배치되는 키의 수가 최소화
- 데이터가 균등 분포 → 수평적 규모 확장
- 핫스팟 키 문제 감소

## 실제로 가상 노드 / 안정 해시가 어디서 사용되는가?

- 수평적 규모 확장 달성에 용이하다고 하는데, 우리가 주로 사용하는 수평적 규모 확장으로는 무엇이 있는가?

## Hash Slot이란 무엇인가?

예시) **Redis Cluster**

- Redis Cluster는 전체 키 공간을 **16,384개의 슬롯**으로 나눔.
- 각 키는 **CRC16** 해시 함수를 통해 슬롯 번호로 매핑.
- 각 슬롯은 클러스터의 특정 노드에 할당.
- 따라서 **슬롯 단위로 데이터 이동(Migration)이 가능**해짐.

## Redis Cluster에서 노드가 추가/삭제될 때

### ➕ 노드를 추가할 때

1. 새 노드는 **"빈손(슬롯 0개)"** 으로 합류.
   그냥 추가하면 슬롯이 하나도 없어서 아무 데이터도 안 받음. 반드시 **리샤딩(reshard)** 필요.
2. 기존 노드들에서 슬롯을 **"걷어와서"** 새 노드에 줌.

**구체적 예시 (슬롯 16,384개)**

```
[추가 전] 마스터 3대
A: 5,461   B: 5,461   C: 5,462

[추가 후] 마스터 4대 → 목표: 각 4,096
A: 4,096   B: 4,096   C: 4,096   D(신규): 4,096
→ A에서 ~1,365, B에서 ~1,365, C에서 ~1,366을 걷어서
  D에게 4,096개 몰아줌
```

**"어디서 몇 개?"는 누가 정하나?**

- `redis-cli --cluster reshard` → **운영자가 직접 지정**
  ("A·B·C에서 총 4,096개를 D로" 식으로 개수·출발노드·도착노드 입력)
- `redis-cli --cluster rebalance` → **도구가 자동 계산**
  ("각 노드가 몇 개여야 균등한가"를 보고 최소한의 슬롯만 이동)

## 🏁 마지막 정리

**1. 문제의 출발점**
`hash % N`은 서버 수가 바뀌면 거의 모든 키가 재배치됨. 이 재배치를 최소화하는 게 핵심.

**2. 안정 해시의 답**
링 + 시계방향 탐색으로 재배치를 `k/n`(최소)로 줄임. 쏠림은 **가상 노드**로 해결하되, 균등함과 저장 공간 사이에 tradeoff가 있음.

**3. 현실 시스템은 "같은 목표, 다른 방식"**
Redis·Kafka는 순수 안정 해시 대신 **고정 슬롯/파티션 + 운영자 통제** 방식을 택함. 이동량은 `k/n`으로 동일하지만, 경계를 **자동으로 정하느냐(링) vs 통제하느냐(슬롯)** 가 차이. 그래서 **슬롯 ≈ 가상 노드**.

**4. Redis Cluster의 노드 추가**
새 노드는 빈손 → `reshard`로 기존 노드에서 슬롯을 결정적으로 걷어옴(랜덤 아님). `reshard`는 운영자 지정, `rebalance`는 도구 자동 계산.

**5. 한 문장 요약**
> 안정 해시·가상 노드는 서버 수가 바뀌어도 이동을 최소화하는 기술이고,
> Redis는 같은 목표를 **16,384 고정 슬롯 + 운영자 통제**라는 다른 방식으로 달성한다.
